# Reports — one failure explained, or one finished capability described

Two kinds, one file each, named `<kind>-<eight or more words joined by dashes>.md`:

| Kind | When it is written | What it holds |
|---|---|---|
| `errors-…` | a failure took real time to understand | the symptom as the person saw it · how it was found · the cause · the cure · how to notice it earlier; the short form also goes into `../anti-patterns.md` |
| `feature-…` | the last step of a capability closes | what the capability does today and how it was proven · which steps built it · what it cannot do and what stays in `../backlog.md` · the person's decisions that shaped it, verbatim · where it lives (files, doors, pages) |

A step summary (`../steps-done/`) says what one step did; a report answers what the element has and in what state.
